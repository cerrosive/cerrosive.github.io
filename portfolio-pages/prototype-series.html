Prototype project 1

overview

  • level concepts
  • lore and worldbuilding

brainstorming

This was the very first digital game project we ever worked on in the BTEC. We were tasked with designing a game idea and creating a prototype.

When I was brainstorming ideas, I was particularly intrigued by the brief's fake name for the "company" we were designing the game for, Polybius. A quick google search and turns out Polybius is an urban legend about an arcade game. I decided to base my ideas off of this.

The urban legend centers around ideas/themes of psychological horror causing players to have amnesia, seizures, night terrors, hallucinations, and the game was said to be very addictive. As a result my game idea centers around similar ideas or themes.

References included in this mindmap are:

  • Hollow Knight
  • Limbo
  • Narrow Dark Cave 2D Pixel Game

In the end, I went for a survival-based game with a sanity mechanic, where the player must survive in the current map for a certain period of time while having to handle enemies coming at them as well as keeping their own sanity in check.

designing the game

Here's a list of the features and mechanics I planned to include:

  • small map area
  • environmental hazards (pits, spikes, etc.)
  • enemy random spawns with pathfinding
  • sanity mechanic in place of health
  • a timer to measure how long the player has survived

I drew up a couple map concepts to decide what would be best. I wanted to keep it simple as this was my first project for my education, while still considering the impacts of the map space for the game.

I settled on concept #1 for my project.

prototyping

Creating the prototype was for the mostpart simple, I didn't have to care about graphics so everything is made up of simple shapes and UI.

The enemies have 4 sites they can spawn from at random, they chase the player but only exist for a certain period of time.

There are also spikes and pits the player must avoid in order to survive.

Most importantly I used a UI slider to create the sanity bar, which the player must keep up otherwise they will lose. This can be done via "concentration", however the player is locked from moving while doing so, requiring a bit of strategising.

coding

Most of the code is simple and minimal, such as the movement code. What I did struggle more with was the pathfinding as I decided to use that over a basic follow script, however this proved to be simpler than expected through the A* Pathfinding Project.

The project provides tools and scripts that allow for simpler setup of pathfinding, I chose to use the more coding-heavy method to learn more about C# and pathfinding.

The only significant issue was the speed, as I accidentally set it too low making it look like it wasn't working, but this was an easy fix simply by changing the speed to higher.

(Note I'm not including the code here because it is not mine, it was learned through a tutorial for the pathfinding project which can be found on YouTube)

There's also a simple script for the timer which helped me get a better understanding of UI coding.
