For our second major assignment we were tasked with building a microgame, similar to warioware. this makes the task simple, all i need is a simple minigame with up to 3 levels that happens within the span of roughly 20 seconds, give or take.

brainstorming

I needed to first figure out exactly what I wanted the microgame to be, I had a few options so I put them all in a table.

Given I only had limited time until the deadline to make this game, I needed to choose something that would be manageable within the timeframe I had.

I ended up colourcoding them in order of priority, as I was allowed to make more than one microgame if I had enough time. I ended up settling with the space invaders-style game as it was the simplest for me to make while still being quite fitting.

designing the game

I quickly sketched out the idea I had in mind for the level and game overall.

Things I wanted to include:

  • cursor-based aiming (instead of left-right movement)
  • 3 levels, increasing number of enemies
  • level 1 = 2 enemies
  • level 2 = 4 enemies
  • level 3 = 5 enemies

I also did a quick sketch of what I wanted the terminal roughly to look like. the idea was that the spaceship has a terminal on the console which is where you would look to actually play the minigame, this is also where things like the countdown during intermission would be."

The designing process for this game was pretty quick and simple because the game itself is quick and simple, there wasn't much needed besides establishing the levels and the difficulty increase, the layout and mechanics of the minigame, and my general ideas for it.

prototyping

Building the prototype was very simple, I had coded simple space invader-style games before, plus I already had the code for the cursor-based aim from a previous project, so this wasn't difficult to implement.

I created a simple set up with a player, enemy, and a bullet pool. the player I made a parent with a player sprite component and shoot point component, and in the code used my previously made cursor-based aiming to make the entire player parent rotate in the direction of the cursor.

Later on for level difficulty I would make different parents to group enemies together for each level, and they would activate and deactivate according to what level the player is currently on.

The minigame and the intermission are made as separate scenes, as part of the project was learning about scene switching. the gameManager controls all variables that need to be carried across scenes.

From there it was quite simple to make all the sprite and animation assets and replace the placeholder sprites.

animation setup

Most of the animation setup is pretty simple:

  • play on start for timer, shoot indicator, default ship anims
  • timed animation for the open/close animation
  • played on met condition for enemy death animations

For the intermission animations it took a bit more setup. I needed the game to open up with just the countdown, but for after a minigame round I needed it to play win/lose first before the countdown.

I achieved this by creating an empty animation as the default animation on entry, then used boolean parameters to determin which animation should play.

When the game first starts the parameter for the countdown is active so it is immediately played, but once the minigames start this boolean is disabled, and the win/lose booleans then determine which respective animation plays when returning to the intermission before transitioning back to the countdown.
